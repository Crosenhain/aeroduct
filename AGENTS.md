# Working on AeroDuct

Guidance for coding agents (and humans) contributing to this repository.
`README.md` says what the program does; `CONTRACT.md` says how it is built
and which physics decisions are settled. Read both before changing anything.

## Ground rules

1. **`CONTRACT.md` is binding.** Never bypass `ad-gpu`; all DDF indexing goes
   through `EsotericPull`; direction pairs `(1,2),(3,4),…` are fixed;
   millimetres everywhere outside `LatticeUnits`. If the contract needs to
   change, change the document in the same commit and say why.
2. **One GPU job at a time.** The solver is bandwidth-bound; a second GPU
   client (a test run, a benchmark, a game) moves every throughput and timing
   number by 2x or more. Never run a simulation and the test suite together.
   Idle GPU shows as low SM clock, not just low utilisation.
3. **Justify GPU hours.** A headless run of 3,000 steps at 0.75 mm is ~30 s;
   a resolution sweep is tens of minutes. Before a long run, say what question
   it answers and what result would change the code. Do not run sweeps to see
   what happens.
4. **GPU tests must skip, not fail, without an adapter.** CI runners have no
   Vulkan device. Use `ad_geom::test_gpu()` and `ad_geom::test_stl_path()`
   and return early on `None`.
5. **Every GPU kernel has a CPU twin.** `ad_solver::ReferenceLbm` mirrors the
   WGSL step for step; a change to one is a change to both, and
   `validation/lbm/gpu.rs` proves they still agree. Same pattern for the
   voxeliser (`ray_parity_voxelize`).
6. **Tests check invariants, not numbers.** Mass conservation, moment
   closure, round-trips, symmetry. A hard-coded expected value needs a comment
   saying where it came from.

## Commands

```bash
cargo build --release                 # the `aeroduct` binary
cargo test --workspace                # ~1 min; GPU tests included if present
cargo test --workspace --release      # what verify.sh runs
./verify.sh quick                     # suite + headless runs, writes verify-out/
cargo run --release -- "parts/Airflow redirector -two inlet.stl"
```

A headless verification run (see `README.md` for every variable):

```bash
AERODUCT_FRAMES=400 AERODUCT_STEPS=60 AERODUCT_U=3 AERODUCT_MESH=ghost \
AERODUCT_VIEW=left AERODUCT_SHOT=verify-out/run.png cargo run --release
```

The log prints the grid, every mouth found, the boundary cell counts, the
lattice units and the metrics as they converge. Diff those lines between two
runs before looking at the pictures.

From Git Bash on Windows, paths in environment variables need Windows form
(`cygpath -m`) or the app sees a `/c/...` path it cannot open.

## Layout and ownership

| Area | Owns |
|---|---|
| geometry | `crates/ad-geom/**`, `shaders/geom/**`, `validation/geom/**` |
| solver | `crates/ad-solver/**`, `shaders/lbm/**`, `validation/lbm/**`, `crates/ad-cuda/**` |
| render | `crates/ad-render/**`, `shaders/render/**`, `assets/**` |
| metrics | `crates/ad-metrics/**`, `shaders/metrics/**`, `crates/ad-estimate/**` |
| ui | `crates/ad-ui/**` |
| integration | `crates/ad-app/**` |

Shaders live in `shaders/` and are embedded with `include_str!`; edit the
file, rebuild, done. The binary needs no data directory.

Two coordinate frames matter in the app: the **lattice** frame is the STL's
own axes (solver, voxels, boundaries, probes, slices); the **world/car** frame
is the renderer's Y-up world (install pose, obstructions, vents). `ad_ui::pose`
maps between them. The lattice never rotates; only the picture and the things
placed in the room do.

## Conventions

- Doc comments explain *why*, including the measurement or failure that
  motivated a decision. Keep that style; a bare "what" comment is noise.
- Environment variables are the headless API. Each is validated and a bad
  value warns and is ignored; a typo must never produce a zero-cell grid.
- Structural edits that change the lattice (geometry, domain, resolution) go
  through the transactional rebuild in `ad-app` so an out-of-memory keeps the
  old simulation running. Uniform-only changes hot-apply.
- Commit messages: imperative subject, body explains the reason and any
  measured effect. No trailing "Generated by" noise beyond the co-author line.
- Line endings are LF (enforced by `.gitattributes`); scripts and shaders
  break on CRLF.
- Scratch output goes in `sweep-out/` or `verify-out/`, both ignored. Do not
  commit screenshots, logs or `imgui.ini`.

## Known state (September 2026)

- The LBM loss coefficient on the test part is not grid-converged; the 1D
  estimator uses K=0.71. Numbers compare designs, they do not match a
  datasheet. Do not "fix" this by tuning `Cs`.
- Tilted inlet air leaves a residual closure error one row in from the rim;
  the real fix is a velocity bounce-back inlet.
- Free-standing vents more than a few mm from a mouth mostly spill round the
  part; Ctrl+click on a mouth seals the vent to it, which is what a duct test
  wants.
- The lattice velocity is capped so the outlet stays below 0.1 lattice speed;
  two sources into a small outlet otherwise go NaN.
